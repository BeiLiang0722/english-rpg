## 1. 目标用户

**唯一用户：我自己。**

| 属性 | 描述 | 对设计的约束 |
| --- | --- | --- |
| 身份 | 成年英语学习者（有工作/学业，非考试冲刺型） | 单次学习可长可短，不设强制时长 |
| 动机 | 想要**正反馈**：看得见的成长、变强的手感 | 每次会话结束必须出现「本次新增的可见变化」 |
| 反感点 | 打卡压力、断签羞耻、排行榜比较、"今天没学=前功尽弃" | 不允许任何形式的连续记录归零羞辱、不允许社交比较 |
| 设备 | 手机为主，碎片时间；偶尔桌面浏览器 | 单手可操作、单题决策 ≤ 5 秒、可随时中断且进度不丢 |
| 语言基础 | 认识四六级核心词的一部分，遗忘严重 | 默认词库难度为 CET-4/6 高频段 |

**验收锚点**：如果某个功能会让用户产生"我今天没学，所以我是个失败者"的感觉，这个功能就是错的。

## 2. 场景与痛点

| # | 痛点（用户原话式） | 具体场景 | 本版对应解法 | 可验收的表现 |
| --- | --- | --- | --- | --- |
| P1 | **坚持不下来**：靠意志力打卡，三天就断 | 下班/睡前打开 App，看到"今日 0/50"直接关掉 | 把"每日任务"换成"打一局"：一局 = 8 个怪（8 个词），3~5 分钟，不设每日配额，不做断签归零 | 打开 App 到进入第一题 ≤ 3 次点击；单局可随时退出，已获得 XP/金币立即落库不丢 |
| P2 | **反馈太慢**：背了两个月，考不出分数，感觉白背 | 学完一单元没有任何"我变强了"的证据 | 每答一题即时给 XP/连击/血条动画；每局结束给结算面板；等级 1→2 只需 70 XP，**在第 1 局中途就会升级** | 从零开始，第 1 次升级必须发生在第 1 局内（≤ 8 题、≤ 5 分钟），且必须有升级动画与音效反馈；每局结算面板显示"本局 XP + 距下一级还差多少" |
| P3 | **看不到成长**：不知道自己变强在哪 | 无历史、无对比、无掌控感 | 三个"成长仪表"：等级/XP 条、已掌握词数（掌握 = 连续 2 次不同日答对）、错题复活清单 | 首页恒常显示这 3 个数字；每个数字都有可复现的计算公式 |
| P4 | **怕重复劳动**：背过的词反复出现，生的词不出现 | 复习全靠自己判断 | 出题优先级算法：错词 > 待复习词（SRS 间隔到期）> 新词 | 同一局内不重复出同一词；到期复习词优先于新词（权重见 6.7） |

## 3. 核心玩法一句话

> **背单词 = 打怪升级：每个单词是一只怪，答对即命中，连对即连招，答错掉血，清完一局结算金币与 XP，等级和徽章是唯一的进度条。**

## 5. 学习内容范围（第一版）

### 5.1 词库规模与来源（可落地的具体来源）

**第一版词库 = 200 个 CET-4/6 高频词，硬性数量 200，允许 ±0。**

生成方式（一次性构建脚本 `scripts/build-words.mjs`，产物 `public/words.json`，构建后即为静态数据）：

1. **数据源（首选）**：开源词典库 [ECDICT（skywind3000/ECDICT）](https://github.com/skywind3000/ECDICT) 的 `ecdict.csv`（约 76 万词条，字段含 `word, phonetic, definition, translation, pos, collins, oxford, tag, bnc, frq`）。
2. **筛选规则（按顺序执行，结果必须可由脚本复现）**：
   - `tag` 字段包含 `cet4` 或 `cet6`；
   - 保留 `frq`（当代语料库词频）非空且 `frq > 0` 的词条，按 `frq` 升序（数字越小越高频）；
   - 过滤掉长度 < 3 的单词、含空格/连字符的短语、纯专有名词（`word` 首字母在 `translation` 中标注为人名/地名的条目）；
   - 取前 160 条自动入选；
   - 另从用户已有教材中挑选 40 条"我在真实材料里见过但记不住"的词，填入 `user_seed` 列表覆盖自动结果（预留字段，可为空）。
3. **兜底方案（若脚本拉不到 ECDICT）**：改为手工整理 200 词，来源为任何一本正版四六级词汇书的高频单元，逐词录入 5.2 定义的字段；**不允许**用 AI 凭记忆生成释义，则验收不通过。
4. **版权与使用范围**：仅自用、不分发词库数据文件；若将来上架，必须替换为已授权词库，此项写入 README 的 Known Limitations。

### 5.2 每个词条必须包含的字段

```json
{
  "id": "w0001",
  "word": "abandon",
  "phonetic": "əˈbændən",
  "pos": "v.",
  "meaning_cn": "放弃；抛弃",
  "meaning_en": "to leave somebody/something and never return",
  "example": "He abandoned his car in the snow.",
  "example_cn": "他把车丢在了雪地里。",
  "collins": 4,
  "frq": 1023,
  "tags": ["cet4"],
  "audio_url": null
}
```

字段完整性验收：`word / phonetic / meaning_cn / example` 四项**非空率必须 100%**；`audio_url` 允许为 `null`（用设备 TTS 兜底）。

### 5.3 题型（第一版只做 5 种）

| 编号 | 题型 | 出题形式 | 判定规则 | 权重 |
| --- | --- | --- | --- | --- |
| Q1 | 英译中四选一 | 给单词，选中文释义 | 4 个选项，每局内选项不重复词 | 40% |
| Q2 | 中译英四选一 | 给中文释义，选单词 | 4 个选项，干扰项须与正确答案**首字母不同**，避免靠首字母猜 | 25% |
| Q3 | 拼写填空 | 给中文 + 首字母 + 下划线长度提示 | 忽略大小写；允许 1 个字符编辑距离内视为正确，但**记为该词"未掌握"** | 20% |
| Q4 | 听音辨词（TTS） | 播放单词读音，四选一 | 设备无 TTS 时本题型自动跳过，不扣血、不计入题数 | 10% |
| Q5 | 例句填空 | 挖空例句中的目标词，给首字母 | 同 Q3 判定 | 5% |

**Q1/Q2 干扰项生成规则**（必须写进代码，避免"一眼看穿"）：从同词库、同 `pos` 的词中随机取 3 个，且与正确答案的 `meaning_cn` 首字不同。若同 `pos` 候选不足 3 个，允许放宽 `pos` 限制但仍需保证首字不同。

一局 8 题，题型按权重随机分配，**同一局内不重复出现同一词条**。

## 6. 游戏化机制清单（逐条含数值）

### 6.1 XP 获得规则 `【数值】`

| 事件 | XP | 说明 |
| --- | --- | --- |
| 答对 Q1/Q2（选择题） | +10 | 基础分 |
| 答对 Q3/Q5（拼写类） | +15 | 手写比选择难，溢价 50%（Q3 与 Q5 同为 15 分，便于数值计算） |
| 答对 Q4（听音） | +12 | — |
| 首次遇见的词答对（`seenCount == 0`） | 额外 +5 | 鼓励认真看新词 |
| 连对奖励（每局内连击） | 第 3 连 +5，第 5 连 +10，第 8 连 +20 | 每档每局仅触发一次，不叠加 |
| 每日首次开局 | +20 | 一天只给一次，跨日按本地时区 00:00 重置 |
| 一局全对（8/8） | 额外 +30 | 完美局奖励 |
| 答错 | 0 | 不给"参与分" |
| 局内每达成 1 个"击败新词"（该词历史答对次数 0→1） | +5 | 与"首次遇见答对"可叠加，因为语义不同（一个看历史，一个看本局） |

**单局 XP 上限校验**：8 题全对且全为拼写题 = 8×15（基础）+ 8×5（新词）+ 35（连击 5+10+20，每档只触发一次）+ 20（每日首局）+ 30（完美局）= **215**；下限（1 题对且非新词、无任何 bonus）= **10**。验收时用「一局 XP 必须落在 10~215 区间」做断言，并对上述 215 的构造用例写一条单测。

### 6.2 等级曲线（1–20 级）`【数值】`

公式：`needXP(L → L+1) = 60 + 10 × L`（L 为当前等级，取值 1~19），累计 XP 由 0 起算。

| 等级 | 升到下一级需 XP | 到达该级累计 XP |
| --- | --- | --- |
| 1 | 70 | 0 |
| 2 | 80 | 70 |
| 3 | 90 | 150 |
| 4 | 100 | 240 |
| 5 | 110 | 340 |
| 6 | 120 | 450 |
| 7 | 130 | 570 |
| 8 | 140 | 700 |
| 9 | 150 | 840 |
| 10 | 160 | 990 |
| 11 | 170 | 1150 |
| 12 | 180 | 1320 |
| 13 | 190 | 1500 |
| 14 | 200 | 1690 |
| 15 | 210 | 1890 |
| 16 | 220 | 2100 |
| 17 | 230 | 2320 |
| 18 | 240 | 2550 |
| 19 | 250 | 2790 |
| 20（满级） | — | 3040 |

**曲线合理性依据**：单局（8 题，按命中率 75% 估算）约 90~125 XP（当天首局含 +20；完整算式见附录 B1）。等级 1→2 需 70 XP，因此在**第 1 局进行到第 4~6 题时就会升级**，这是全 App 最强的一次正反馈节点，必须在 UI 上做足（全屏升级动画 + XP 条灌满效果）。满级累计 3040 XP ÷ 单局首局 ~120 XP ≈ **25 局**；若只算当天第 2 局起的 ~100 XP，则约 **30 局**，即每天 1 局的话一个月左右看到一个明确的终点。满级后 XP 继续累计并显示为"巅峰值"，不再升级。

**UI 硬要求**：XP 条上必须显示「+N XP」的浮动数字（动画时长 ≤ 400ms），且结算页必须写清「距下一级还差 X XP」；满级时显示"满级"而不是空进度条。

### 6.3 血量 / 生命机制与答错惩罚 `【数值】`

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| 单局血量上限 | 3 颗心 | 一局 8 题，最多容错 3 次 |
| 答错 | −1 心，本局连击立即清零 | 连击清零只在本局内生效，不影响已有 XP/金币/等级 |
| 血量归零 | 本局立即结束，跳结算页 | **已获得的 XP 与金币全部保留**（永不倒扣，这是 P1 痛点的核心对策） |
| 答错后果 | 该词进入"待复活队列"，同一词在**同一局内不再出现**，并在下次开局时提高权重（见 6.7） | 不锁关卡、不冻结账号、不扣金币 |
| 复活机制 | 每局可用 **1 次**「重试」：把上一题重出一次，**不消耗心数**，不改变血量上限 | 额外的一次重试只能用商店的"替身稻草人"（见 6.5）；"护心符"只提高血量上限，不增加重试次数 |
| 连击与血量关系 | 连对 8 题（完美局）额外展示"无伤通关"标签，不给额外数值奖励 | 只做情绪奖励，避免通胀 |

**必须显式声明**：本 App 不存在任何会减少 XP、金币、等级、徽章的惩罚。

### 6.4 连击 streak 判定与断签处理 `【数值】`

定义两套连击，必须分别持久化，UI 上分别展示：

**(a) 局内连击 `combo`**：一局内连续答对次数。答错清零。用于 6.1 的连对奖励。

**(b) 每日学习连击 `dailyStreak`**：

| 规则 | 数值/判定 |
| --- | --- |
| 判定单位 | 自然日（本地时区 00:00 ~ 23:59） |
| 达成条件 | 当日完成 ≥ 1 局（≥ 1 局即算，不要求题数/正确率） |
| 续接 | 连续两天都有局，`dailyStreak + 1` |
| 漏一天 | `dailyStreak` 归零，但提供**自动保护**： |
| 保护机制 | 免费"冰冻卡"每月 **2 张**，自动消耗于漏签当天，效果 = 该天视为已学习，连击继续；用户无需任何操作 |
| 修复机制 | 商店出售"回补卡"（**40 金币**），购买后可修复 1 天漏签；同一个月最多修复 2 天 |
| 上限 | 单个自然月内，冰冻 + 回补合计最多保住 4 天 |
| 永不发生 | 连续记录"清零"的羞辱性弹窗、红色警告、"你已断签 3 天"的提醒文案 |
| 断签后的文案 | 固定为：「连击重新开始了，上次是 N 天。今天继续。」 |

**理由（不确定项，已在第 10 节提出拍板）**：对成年人来说，断签的挫败感 > 连击的成就感。因此把"惩罚"改成"默认保护 + 小额付费修复"，代价是数值上连击会显得没那么"硬"，但更符合 P1。

### 6.5 金币用途与商店（可选模块，默认实现） `【数值】`

**金币获取**：

| 事件 | 金币 |
| --- | --- |
| 答对 1 题 | +2 |
| 一局结束（结算） | +10 |
| 每日首次开局 | +15 |
| 完美局（无伤 8/8） | +20 |
| 升 1 级 | +30 |
| 解锁 1 个徽章 | +25 |
| 答错 | 0（不倒扣） |

**商店物品（v1 只 4 件，全部为纯游戏内效果，无任何现实奖励）**：

| 物品 | 价格（金币） | 效果 | 限购 |
| --- | --- | --- | --- |
| 护心符 | 60 | 本局血量上限 +1（仅下一局生效） | 每日 2 个 |
| 回补卡 | 40 | 修复 1 天漏签，连击续接 | 每月 2 个 |
| 侦查之眼 | 30 | 下一局开局即排除 Q1 中 1 个错误选项（每题生效 1 次，共排除 3 次） | 每日 1 个 |
| 替身稻草人 | 80 | 下一局首次血量归零时以 1 颗心复活继续 | 每日 1 个 |

**经济平衡验收（必须跑模拟）**：写一个 `simulate(days, roundsPerDay, accuracy)` 脚本，默认参数 `simulate(30, 1, 0.75)`，断言：

- **稳态月收入**（只计每日性收入：答对金币 + 结算 + 每日首局）落在 **700 ~ 1150 金币**（推导见附录 B）；
- **首月累计收入**（稳态 + 升级奖励 + 徽章奖励，均为一次性）落在 **1500 ~ 2200 金币**，且断言首月「可购买物品总数 ≥ 15 件」；
- 命中率改到 100% 重跑，稳态月收入 **≤ 1150**（防止"全对就通胀"）；
- 限购约束下，**任何一个月**的总支出上限都 `> 当月收入`（金币永远不够花完所有限购）。

### 6.6 成就徽章清单（v1 共 11 个，满足"至少 8 个"要求）

数据结构：`{ id, name, desc, condition, checkOn, coinReward, xpReward }`，条件必须可由存档数据纯函数判定。

| # | 徽章 | 解锁条件（可判定） | 奖励 |

### 6.7 出题优先级算法（支撑 P4，必须实现）

每局选 8 个词，按以下优先级排序取前 8：

1. **错词复活**：`wrongCount > 0` 且 `lastWrongAt` 距今 > 6 小时，权重最高（`priority = 100`）；
2. **SRS 到期**：`nextReviewAt <= now`，按 `nextReviewAt` 升序（`priority = 80`）；
3. **新词**：`seenCount == 0`（`priority = 60`，按词库顺序取）；
4. **巩固**：其余已学词（`priority = 20`，按 `lastSeenAt` 升序）。

SRS 间隔（答对后 `nextReviewAt = now + interval`）：第 1 次答对 → 1 天；第 2 次 → 3 天；第 3 次 → 7 天；第 4 次 → 16 天；第 5 次及以后 → 35 天。答错则 `interval` 重置为 1 天。

"已掌握词数"的定义（首页显示）：`连续 2 次跨天答对` 的词数。此定义必须与 6.6 的 B4 徽章使用同一个判定函数。

## 10. 需要你拍板的问题（5 个）

| Q1 | **一局的题数固定 8 题，还是让用户选 5/8/12？** | 固定 8 题 | 8 题 ≈ 3~5 分钟，正好一个碎片时间；固定值让 XP/血量的平衡可精确计算，不用做三套数值 |

## 附录 B：关键数值推导（供 AI 自检，不要跳过）

**B1 单局 XP（8 题、命中率 75%、6 对 2 错、6 个新词命中 4 个）**

新词首答对额外：4 × 5                                              =  20
连击奖励：连对档位只触发 5(+10) 与 3(+5) 两档（中途答错打断）      =  15
每日首局（当天第一次）                                             =  20
────────────────────────────────────────────────────────────────────
合计 ≈ 122；若当天第 2 局起，则为 102
```

→ 支撑 6.2 的「单局约 90~125 XP」与附录 B2 的收入口径（当天第 2 局起约 102 XP）。

**B2 30 天金币收入（每天 1 局、命中率 75%、每局 6 个新词）**

```
【每日性收入（稳态口径）】
答对 6 题 × 2 金币                        = 12/局
一局结算                                   = 10/局
每日首次开局                               = 15/天
                                          每局小计 37 → 37 × 30 = 1110
完美局 +20：75% 命中率下拿不到，故稳态不计

【一次性收入（首月）】
升级奖励：30 天累计 XP ≈ 102 × 30 = 3060（另 B2 给 50 XP）→ 到达 20 级
          共升 19 级 × 30 金币            = 570
徽章奖励：11 个徽章按 6.6 合计            = 400
          （B1/B2/B4/B5/B7/B8/B9/B11 各 25 = 200
            ＋ B3 50 ＋ B6 50 ＋ B10 100 = 200）
                                          一次性小计 = 970
────────────────────────────────────────────────────────────
稳态月收入   = 1110
首月累计收入 = 1110 + 970 = 2080
```

→ 结论：**稳态月收入 ≈ 1110**（落在 A8 的 `[700, 1150]` 区间内）；**首月累计 ≈ 1780（只触发 5 个高概率徽章：1110 + 570 + 125）~ 2080（全部 11 个徽章解锁：1110 + 570 + 400）**，均落在 A8 的 `[1500, 2200]` 区间内。

**B3 限购约束下的支出上限（每月）**

```
护心符 60 × 2/天 × 30  = 3600
侦查之眼 30 × 1/天 × 30 =  900
替身稻草人 80 × 1/天 × 30 = 2400
回补卡 40 × 2/月       =   80

**B4 等级曲线累计公式自检**

代入 n=20：`60×19 + 5×19×20 = 1140 + 1900 = 3040` ✅ 与 6.2 表格一致。
