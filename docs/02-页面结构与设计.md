## 1. 页面清单与信息架构

### 1.1 路由清单

技术形态为单页应用，7 个页面 + 1 个全局覆盖层。路由用 Hash 模式，保证直接双击 `index.html` 也能跑（无需服务器）。

| # | 页面 | 路由 | 类型 | 页面目标 | 出口 |
| --- | --- | --- | --- | --- | --- |
| P0 | 启动/加载页 | `#/boot` | 过场 | 读存档、初始化词库索引，≤600ms | 自动跳 P1 |
| P1 | 主页（今日战斗） | `#/home` | 枢纽 | 一屏内回答「今天该干什么」，一键开打 | 任意页 |
| P2 | 答题页（战斗） | `#/battle/:levelId` | 沉浸 | 逐题作答，即时反馈 | P3 / P1 |
| P3 | 结算页 | `#/result/:sessionId` | 反馈 | 把刚刚的战斗换成看得见的成长 | P1 / P2 |
| P4 | 等级与成就页 | `#/progress` | 展示 | 看等级曲线进度 + 徽章墙 | P1 |
| P5 | 词库/关卡选择页 | `#/levels` | 选择 | 选关、看每关掌握度 | P2 |
| P6 | 设置页 | `#/settings` | 配置 | 改玩法参数与偏好、管理存档 | P1 |
| P7 | 数据统计页 | `#/stats` | 展示 | 看长期趋势与错词分布 | P1 |
| — | 全局覆盖层 | 无路由 | 覆盖 | 升级动效、成就解锁、确认弹窗 | 关闭回原页 |

数据统计页拆成 P7 而非并入 P4：P4 回答「我变强了多少」（等级、经验、徽章），P7 回答「我的学习状态如何」（正确率、错词、时长、趋势）。两者读取同一份存档，但受众和刷新频率不同——P4 每场战斗都看，P7 隔几天才看。

### 1.3 导航模型

**枢纽-辐射式（hub-and-spoke），不用底部 Tab 栏承载全部页面。**

理由：本 App 的主行为只有一个——「开始今日战斗」。底部 Tab 栏会把注意力均分给「统计 / 设置」这类低频页面，削弱主行为的显著性；而「今日战斗」需要一个几乎无摩擦的入口，且战斗页本身应全屏沉浸、不带导航干扰。

因此导航分三层：

1. **一级入口（主页）**：今日战斗 CTA + 四宫格（关卡 / 等级成就 / 数据 / 设置）。
2. **全局返回**：所有 P4–P7 页面左上角固定「← 返回」，点击回 `#/home`；浏览器后退键等效。
3. **沉浸模式**：P2 答题页隐藏全局导航，只保留顶部「×」退出（需二次确认，防止误触丢进度）。

### 1.4 跨页共享的全局状态条（HUD）

主页与关卡选择页顶部共享一条 HUD，保证用户在任何「准备态」都能看到自己的资源，形成持续的正反馈：

```
[ 头像/等级圆章 Lv.3 ]  [ XP 条形进度 320/500 ]  [ 🪙 240 ]  [ 🔥 5天 ]
```

答题页不复用这条 HUD，改为战斗专用 HUD（进度 + 血量），避免同时出现两套进度语义。

### P2 答题页（战斗）`#/battle/:levelId`

| 顺序 | 模块 | 内容 | 数据来源 |
| --- | --- | --- | --- |
| 1 | 战斗 HUD | 左「×」退出；中「第 3 / 10 题」+ 4px 进度条；右 3 颗心（已扣的显示为空心/灰） | `session.index`、`session.hp` |
| 2 | 题目卡 | 题型标签（英译中 / 中译英 / 听音）；题干大字（英文单词 30px / 中文 26px）；音标与词性（英译中时显示）；可选「🔊 发音」按钮；可选例句（默认折叠，点「例句」展开） | `question.word`、`question.type` |

| 4 | 反馈条 | 作答后在选项下方原地展开：`✓ 正确 +10 XP` 或 `✗ 答错` + 正确答案 + 一行中文释义；连击时追加 `🔥 连击 ×3 +15` | `session.lastResult` |

| 顺序 | 模块 | 内容 | 数据来源 |
| --- | --- | --- | --- |

## 3. 关键交互流程

主流程：**进入 App → 选择关卡 → 逐题作答 → 即时反馈 → 结算获得 XP → 升级动效 → 返回主页**。
下表逐步给出「用户动作 → 界面变化 → 状态变化 → 系统副作用」。XP 数值为中心基线，与阶段 1 定稿值不同时只改本表下方数值表。

### 3.1 主流程逐步拆解

| 步 | 用户动作 | 界面变化 | 状态变化 | 系统副作用 |
| --- | --- | --- | --- | --- |
| 1 | 打开 App | 显示 P0：图标 + 进度条（≤600ms） | 内存态 `booting → ready` | 读 localStorage 存档；无存档则建默认档；解析词库 JSON，建立 `wordId → mastery` 索引 |
| 2 | 自动跳转 | P0 淡出（200ms），P1 淡入 | `route = #/home` | 计算「今日」是否已有完成记录（本地日期 00:00 为界）；刷新 streak（见 3.3） |
| 3 | 看主页 | 今日战斗卡按状态渲染；若未完成则显示「今日首战 +50%」；连续天数徽章保留 | — | 无写入 |

### 3.3 断签判定逻辑（易错点，先定死）

```
读档后：
  today    = 本地日期（YYYY-MM-DD）
  lastSeen = profile.lastStudyDate        // 上次完成战斗的日期
  gap      = today - lastSeen (天)

  if gap == 0        → streak 不变（今天已签到，再打不重复计）
  if gap == 1        → streak 不变（今天还没打，判定推迟到本场结束时 +1）
  if gap >= 2        → 断签：若补签券 > 0 则消耗 1 张，streak 保持；否则 streak = 0
```

判定时机有两处，必须一致：**启动时**（用于主页显示）与**本场结算时**（用于真实累加）。不允许只在结算时判定，否则用户会看到一个过期的连续天数。

## 5. 视觉方向

设计基调：**深色游戏化 + 高信息聚焦**。深色底让进度条、连击光效、徽章金色形成最强烈的对比，同时符合「晚上背单词」这一主要使用场景；不使用高饱和跑马灯式配色，避免长时间阅读疲劳。

### 5.1 配色方案（可直接粘贴的 CSS 变量）

**配色硬规则**（写代码时必须遵守，否则对比度不达标）：

1. 主色 `--accent` **不得**直接作为 `--bg-base` 上的正文文字色，改用 `--accent-text`。
2. 主色按钮上的文字用 `--accent-on`（白），**不要**用深色文字（深色 on `#6C5CE7` 仅 3.90:1，不达 AA）。
3. 金色 `#FFC94A` 只用于深色主题；浅色主题用 `#946200`。
4. 语义色的**背景**永远用 `-bg` 变体（透明度 10–16%），不要用纯色块铺满，否则正文对比度失控。
5. 状态不能只用颜色区分（见第 7 节），必须同时有图标或文字。

### 6.3 桌面专属增强（不改变信息架构）

2. **悬停态**：卡片 hover 抬升 2px + `--shadow-md`；手机端无此态，不依赖 hover 传达任何信息。
3. **导航栏常驻**：桌面用左侧固定导航栏替代底部导航，避免鼠标长距离移动；移动端底部导航仅在视口高度 < 700px 时出现（大屏手机可直接用主页四宫格）。

## 7. 可访问性

目标：达到 **WCAG 2.1 AA** 级。以下每条都可验收。

### 7.1 键盘操作

| 场景 | 按键 | 行为 |
| --- | --- | --- |
| 全局 | `Tab` | 按 DOM 顺序在可聚焦元素间移动；焦点顺序与视觉顺序一致 |
| 全局 | `Shift + Tab` | 反向移动 |
| 全局 | `Enter` / `Space` | 激活当前聚焦元素 |
| 全局 | `Esc` | 关闭覆盖层/弹窗；答题页中 = 触发退出确认 |
| 答题页 | `1` `2` `3` `4` | 选择 A/B/C/D 选项（等价点击） |
| 答题页 | `↑` `↓` | 在选项间移动焦点（Radio 语义） |
| 答题页 | `Enter` | 已作答时 = 下一题；未作答时 = 跳过 |
| 答题页 | `Space` | 播放当前单词发音 |
| 结算页 | `Enter` | 触发主按钮（再来一关 / 返回主页取默认焦点在主按钮） |
| 任意列表 | `↑` `↓` `Home` `End` | 列表内移动 |

实现要求：

- **自定义控件必须补齐语义**：选项列表用 `role="radiogroup"` + `role="radio"` + `aria-checked`，或用原生 `<input type="radio">` 视觉隐藏；进度条用 `role="progressbar"` + `aria-valuenow/min/max`。
- **焦点可见**：`:focus-visible { outline: 2px solid var(--accent-text); outline-offset: 2px; }`。禁止 `outline: none` 而不给替代样式。
- **焦点陷阱**：覆盖层打开时焦点锁在层内，`Esc` 或关闭后焦点**归还到触发元素**。
- **跳过链接**：页面首个可聚焦元素为「跳到主内容」，视觉隐藏、聚焦时显示。
- **不依赖 hover**：所有 hover 才有信息的功能（如徽章详情 tooltip）都必须有点击/键盘等价路径。

### 7.3 字号与可读性

- 正文默认 **16px**，最小 **14px**；12px 仅用于单位与角标（不承载唯一信息）。
- 行高：正文 1.6，中文题干 1.35，英文单词 1.2。
- 提供字号档位：标准 / 大（×1.125）/ 特大（×1.25），通过根字号缩放，全站使用 `rem`。
- 长文本限制行宽 **≤ 38 个中文字符**（约 680px），桌面端不铺满整屏。

### 7.4 屏幕阅读器与语义

- 页面结构用 `<header> <main> <nav> <section>` + 每页唯一 `<h1>`，标题层级不跳级。
- 动态内容播报：作答反馈用 `aria-live="polite"` 区域播报「答对，加 10 经验」/「答错，正确答案是 C 归还」；血量变化播报「剩余 2 颗心」；升级用 `aria-live="assertive"` 播报「升级到 4 级」。
- 状态双重编码：正确/错误**同时**用颜色 + 图标 + 文字（✓/✗ + 「答对了」），色盲用户（约 8% 男性）可辨；连击、血量均带数字。
- 图表（P7）必须提供文字替代：`<figure>` + `<figcaption>` 文字摘要（如「近 7 天正确率从 62% 上升到 85%」），并提供「以表格查看」切换，输出 `<table>`。
- 图标按钮必须有 `aria-label`（如「退出战斗」「播放发音」）；纯装饰图标 `aria-hidden="true"`。
- 发音按钮除音频外提供可见文本与 `aria-label`，不依赖声音传递唯一信息（听障用户仍可读题）。
- 表单控件用真实 `<label for>` 关联；开关用 `role="switch"` + `aria-checked`。

### 7.5 其他

- **触控目标** ≥ 44×44 CSS px（选项 56px 高，符合）。
- **颜色非唯一手段**（见 7.4）；**不自动播放声音**，发音需用户主动触发（尊重设置中的「自动发音」由用户开启）。
- **动画可关**：`prefers-reduced-motion` 或设置页「减弱动效」都能关闭 A08/A10/A13/A14/A16。
- **不使用闪烁**：任何闪烁不超过 3 次/秒（红闪为 2 次，合规）。
- **语言标注**：`<html lang="zh-CN">`；英文单词与音标用 `<span lang="en">` 包裹，保证屏幕阅读器切换发音语种。
- **错误可恢复**：重置存档等破坏性操作需输入确认词，且提供「导出存档」先行备份入口。
