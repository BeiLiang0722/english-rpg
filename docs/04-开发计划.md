## 0. 本计划与 PRD 的差异说明（必读，3 条）

PRD 是按 TypeScript + React + Zustand + Vite 写的（文中的 `src/pages/Home.tsx`、`src/config/balance.ts`、`npm run dev` 等为笔误性质的工程描述）。本计划改用纯前端零构建方案，因此有 **3 处必须显式裁决的差异**，其余全部照抄 PRD。

| # | PRD 原文 | 本计划定稿 | 理由与影响 |
| --- | --- | --- | --- |
| **D1** | 文件为 `.ts` / `.tsx`，用 Zustand 单 store，构建产物为 PWA | 全部改为 **`.js` + 全局命名空间 `window.WQ` + 经典 `<script>` 顺序加载** | `file://` 协议下 ES Module（`type="module"`）受 CORS 限制无法加载，`import` 直接失败；「双击即用」是一票否决需求。**页面结构、路由、数值、字段名 100% 不变**，只换语言与加载方式。 |
| **D2** | 词库是 `public/words.json`，运行时 `fetch` 读入 | 词库是 **`src/data/words.js`**（`WQ.WORDS = [...]`），同时产出 `src/data/words.json` 作为**可校验副本** | `file://` 下 `fetch('words.json')` 抛 CORS 错误。改为 `<script>` 直接引入数据文件，`file://` 可用且无异步等待（PRD §3.3 的 `#/boot ≤600ms` 更稳）。JSON 副本仅供人工核对与 `dev/check-words.mjs` 校验，**不是运行时依赖**。 |
| **D3** | PWA（`manifest.json` + Service Worker，验收 A12） | **降级为「离线可用」验收**：断网能完整打一局（本来就不需要网络）；Service Worker 从 v0.1 移除，登记进 v0.2 待办 | Service Worker 在 `file://` 下**无法注册**（浏览器硬限制，非代码问题），与「双击即用」不可兼得。PRD §7.5 的实质要求「断网可完整打一局」在零网络架构下天然满足，故 A12 改为「断网 + 清 HTTP 缓存重开页面仍可玩」验证。 |

**D3 的取舍说明**：若将来需要 PWA 安装能力，只需在 `english-rpg/` 下起一个静态服务器（`python -m http.server`）即可启用，本计划的所有代码**无需修改**（词库已同时存在于 `.js` 与 `.json` 两种形态，路由是 hash 模式，资源全是相对路径）。这条路径保留在 README 的 Known Limitations 里。

## 1. 技术选型与理由

### 1.1 选型结论

| 维度 | 定稿 | 版本/形态 |
| --- | --- | --- |
| 语言 | 原生 HTML5 + CSS3 + ES2020 JavaScript | 无 TypeScript、无 JSX |
| 依赖 | **零**（`dependencies` 与 `devDependencies` 都为空） | 无 `node_modules` 概念 |
| 构建 | **无**。没有打包器、没有转译、没有压缩步骤 | 源码即产物 |
| 加载方式 | 经典 `<script src>` 按序加载，每个文件一个 IIFE，挂载到 `window.WQ` | 兼容 `file://` |
| 样式 | 3 个 CSS 文件：设计 token / 布局组件 / 页面样式 | 无预处理器、无 PostCSS |
| 渲染 | 字符串模板 + `insertAdjacentHTML` 整页替换（配合事件委托） | 无 Virtual DOM |
| 状态 | 单一可序列化状态对象 `WQ.store`，与存档同构（照抄 PRD §3.4 的思想） | 无状态库 |
| 持久化 | `localStorage`，4 个键（照抄 PRD §6.1） | 无 IndexedDB、无后端 |
| 路由 | `location.hash`（照抄 PRD §3.3 路由表） | 无路由器库 |
| 音频 | 音效：WebAudio 合成（免资源文件）；发音：`speechSynthesis` | 无音频库、无 mp3 |
| 测试 | 浏览器内 `#/selfcheck` 断言页（主）+ `dev/check-words.mjs`（仅词库校验，可选） | 无 Jest、无 Playwright |
| 运行前提 | **双击 `english-rpg/index.html`** | 不需要服务器、不需要命令行 |

### 1.2 为什么不上框架（逐条回答）

1. **「双击 `index.html` 即用」与打包器天然对立。**
   React/Vue/Svelte 的源码必须经过编译才能跑，产物要么是一个 `bundle.js`（那就要维护构建产物，等于把源码和产物两份东西同时对），要么依赖开发服务器。而本项目的核心用户场景是「一个成年人晚上打开电脑/手机浏览器，双击一个文件，背 5 分钟单词」。引入构建链会让「改一行字」变成「改源码 → 跑 build → 刷新」，直接抬高后续维护成本。
2. **`file://` 会杀死所有现代模块化方案。**
   浏览器对 `file://` 的 `fetch`、ES Module、Service Worker 全部按跨域拒绝。框架生态默认这三样都要用（动态 import、fetch 数据、PWA 插件）。要在 `file://` 下跑框架，必须换成 UMD 全量包 + 内联数据，等于把框架的最大优势（工程化）全部砍掉，只留下体积和心智负担。
3. **本项目的界面复杂度撑不起框架的收益。**
   全部 UI 是 6 个页面（照抄 PRD C13 裁决：营地 / 对局 / 结算 / 成长（4 Tab）/ 商店 / 设置）+ 一组覆盖层。没有复杂表单、没有长列表虚拟滚动、没有频繁局部更新（唯一的频繁更新是「选项判定后原地展开反馈条」，一次 `innerHTML` 替换就够）。React 的 diff 在这里不会比「重新渲染当前页面片段」更快，也不会更省代码。
4. **状态是天然单例且要整体序列化。**
   PRD §3.4 要求「唯一持久化对象 `save`」。这在零依赖下就是一个普通对象 + 一个 `persist()` 调用；用 Zustand/Redux 反而要额外写「哪些字段进存档、哪些不进」的中间件。
5. **体积与首屏。**
   PRD §3.3 要求 `#/boot` ≤ 600ms、A1 要求冷启动 ≤ 15 秒。零依赖下首屏只有 HTML + 3 个 CSS + 十几个小 JS + 一个 ~60KB 的词库数据文件，本地打开是**毫秒级**。引入框架后，光框架本体就 40–140KB，且要等解析执行。
6. **可交付性与可审计性。**
   交付物是「能直接双击的东西」，不是「能 `npm run build` 的仓库」。验收人（包括未来的自己）不需要装 Node、不需要能联网装包，打开就能逐条核对 PRD 验收清单。

**框架会在什么条件下重新考虑**（写下来防止争论）：① 页面数超过 20 个且存在跨页共享的复杂交互状态；② 需要多人协作并有大量局部状态；③ 需要 SSR/SEO；④ 需要上架并接入支付/登录/云同步（PRD §9.2 已明确 v0.2 也不做）。以上四条在 v0.1/v0.2 都不成立。

### 1.3 零依赖带来的 4 个必须自行解决的问题（提前定死方案）

| 问题 | 框架下的做法 | 本计划的替代方案 | 落在哪个任务 |
| --- | --- | --- | --- |
| 模块化 | `import` / 打包 | 每个文件一个 IIFE，挂到 `WQ` 命名空间；文件间只通过 `WQ.xxx` 通信 | T1.8 |
| 响应式更新 | 数据绑定 / diff | **整页重渲染**：`render()` 用模板串生成 HTML，一次性写入 `#app`；交互靠 `#app` 上的一层事件委托（`data-action` 属性分发） | T1.8、T1.10 |
| 事件清理 | 框架自动解绑 | 委托唯一入口 + `location.hash` 变更时先移除监听；禁止在页面渲染函数里对**会消失的 DOM** 用 `addEventListener` | T1.9、T1.10 |
| 原生控件语义 | 组件库 | 手写：选项用 `role="radiogroup"/radio` + `aria-checked`，开关用 `role="switch"`，进度条用 `role="progressbar"`（照抄 02 §7.1 要求） | T4.2 |

### 1.4 语言子集与硬禁令

**允许**：`const/let`、箭头函数、模板字符串、解构、展开、可选链 `?.`、`Array.prototype.{map,filter,reduce,find,some,flat}`、`Map/Set`、`Intl.DateTimeFormat`、`crypto.randomUUID()`（带降级）、`requestAnimationFrame`、CSS 自定义属性、CSS `grid/flex`、`@media (prefers-reduced-motion)`。

**禁止**（保证 `file://` 与低端机可用）：
- `import` / `export` / `type="module"`；`fetch()`（词库数据内联）；`navigator.serviceWorker`；`Worker`；
- 任何 `eval` / `new Function`（CSP 友好，也便于审计）；
- 任何 CDN 外链（字体、图标、库一律不用；图标用内联 SVG 或 emoji）；
- 任何 `innerHTML` 拼接**未转义的用户输入**（拼写题答案、昵称、导入的 JSON 一律走 `esc()` 转义，见 T1.11）。

### 2.1 各文件职责与「不许做什么」

| 文件 | 唯一职责 | 禁止事项 |
| --- | --- | --- |
| `index.html` | 声明 `<html lang="zh-CN">`、meta viewport/theme-color、按序引入 4 CSS + 全部 JS、提供 `#app`/`#toast-root`/`#overlay-root`/`#live-region` 容器、`<noscript>` 提示 | 不写任何内联样式表以外的业务逻辑；不写行内 `onclick` |
| `styles/tokens.css` | 02 §5 的 CSS 变量全量落地 | 不写任何选择器样式，只允许 `:root` / `:root[data-*]` |
| `styles/base.css` | reset、`html { font-size }` 档位、正文排版、`:focus-visible`、`prefers-reduced-motion`、`.visually-hidden`、`env(safe-area-inset-*)` | 不写页面级布局 |
| `styles/components.css` | 跨页复用组件（按钮/卡片/进度条/选项/心/覆盖层/Toast/徽章/Tab） | 不写只在某一页出现的布局 |

## 5. 风险与对策

### R1 · 中文字体渲染

| 项 | 内容 |
| --- | --- |
| **风险** | ① 不引入 Web Font（02 §5.2 已定），Windows 上「微软雅黑」与 macOS「苹方」的字重、字宽、行高差异大，同一套 `px` 排版在两端一行能放下/放不下；② 深色底 + 细体中文字在小屏上发虚、笔画糊；③ 正文里混排英文单词（题干 30px）与中文释义时基线不齐；④ 某些 Windows 上系统缺 `Segoe UI` 的 CJK 回退，可能出现方框或宋体回退；⑤ 字号档位（×1.125/×1.25）下中文行高不够会挤在一起。 |
| **触发信号** | 同一段文案在两端换行位置不同；题干中文出现「半行掉下去」；DevTools 里 `font-family` 实际解析到 `SimSun`/`Times New Roman`。 |
| **对策（预防）** | ① 字体栈照抄 02 §5.2，**中文字体放在西文之后**（先 `-apple-system/Segoe UI`，再 `PingFang SC/Microsoft YaHei`），保证西文用系统西文字体、中文用系统中文黑体；② 全局 `body { font-weight: 400; -webkit-font-smoothing: antialiased; text-rendering: optimizeLegibility; }`；③ 中文行高给足（正文 1.6、中文题干 1.35，照 02 §7.3），**不用固定 `line-height: px`**；④ 关键中文块（按钮、选项、卡片标题）全部用 `flex` + `min-height` 而不是固定高度，允许换行不溢出；⑤ 长文本行宽 ≤ 38 中文字符（02 §7.3）；⑥ 字号档位用 `rem` + `html{font-size:%}` 整体缩放，禁止在任何地方写死 `px` 字号（只有 token 定义处例外）。 |
| **对策（检测）** | T4.6 验收里加一条「三档屏宽 × 两端浏览器各截一次图」；自检面板加一条断言：`getComputedStyle(document.body).fontFamily` 包含中文黑体名。 |
| **兜底** | 若某端出现明显错位：① 该块改用 `display:block` + 独立行；② 缩小该处字号档位；③ 极端情况下允许为中文单独加 `font-family: "Microsoft YaHei", "PingFang SC", sans-serif` 的 `.zh` 工具类，但**不引入字体文件**。 |

### R2 · 动画卡顿

| 项 | 内容 |
| --- | --- |
| **风险** | ① 低端 Android / 老 Windows 笔记本上，`filter: blur()` + `box-shadow` 大面积重绘会掉帧（升级覆盖层的 blur + 金光环是重灾区）；② 升级动效 420ms spring + 两圈光环 + 徽章卡排队，多个动效叠加时同时运行超过 3 组（违反 02 §5.4 硬约束）；③ 结算页数字滚动 + XP 条 + 覆盖层同时启动，一帧内触发多次布局；④ 一次性 `innerHTML` 整页替换后立刻跑 `requestAnimationFrame` 动画，可能错过首帧导致「跳一下」。 |
| **触发信号** | 升级动效明显顿一下；DevTools Performance 录制里出现长任务 > 50ms，或 FPS 低于 45；移动端滚动时列表发涩。 |
| **对策（预防）** | ① **只动 `transform` 和 `opacity`**，禁止动 `width/height/top/left`（XP 条除外，它用 `transform: scaleX()` 实现填充）；② 升级覆盖层：blur 只加在蒙层一处并 `will-change: opacity, backdrop-filter`，动画结束立即 `remove` will-change；③ 严格串行：升级层 → 收起后才播徽章卡（T3.3 就是这个顺序），并用一个全局「动效队列」保证同时运行 ≤3 组；④ 页面渲染完成后用 `requestAnimationFrame` 的**双重调用**（下一帧再加类）触发入场动画，避免首帧被合并；⑤ 动效时长全部走 token（`--dur-*`），一处可全局降速；⑥ `prefers-reduced-motion` 与设置页「减弱动效」走同一条降级路径（`html[data-motion="reduced"]`），降级时 **A08/A10/A13/A14/A16 直接关闭**（照 02 §5.4 的 A20）。 |
| **对策（检测）** | T4.5 加一条 DevTools Performance 录屏验收：录「结算 → 升级 → 徽章」全段，**无长任务 > 50ms**；在 Chrome 的 CPU 4x Throttle 下重录，功能仍完整（允许变慢，不允许动画中断/状态错乱）。 |
| **兜底** | 若目标设备仍卡：把金光环从 CSS 动画改为单张 SVG 描边渐变 + `transform`，并把 blur 半径从 2px 降到 0（保留 80% 蒙层，视觉差异极小）。 |

### R3 · 题库质量

| 项 | 内容 |
| --- | --- |
| **风险** | ① **干扰项凑不出来**：Q1 要求 3 个干扰项的中文释义**首字不同**、Q2 要求首字母不同；如果 200 词里同 `pos` 的候选少、或中文释义首字大量重复（如都是「使…」），会出现「只能放宽规则」甚至无解；② **一眼看穿**：干扰项与正确答案语义差距过大（如 `abandon` 的干扰项是 `apple`），选择题变成送分题，违背 01 §5.3 的初衷；③ **释义/例句错误**：兜底方案是手工录入，容易打错字、写错词性、例句里根本不含目标词；④ **Q3/Q5 拼写题无法判定**：编辑距离 1 在所有短词上都可能误判（如 `cat/car`），且 Q5 挖空可能挖到例句里出现多次的词；⑤ **近似拼写规则被滥用**：`approximate=true` 但 PRD 要求「记为未掌握」，容易漏实现导致 SRS 被错误推进。 |
| **触发信号** | 出题时 `buildOptions` 返回不足 4 项；同一局里两个选项释义几乎同义；用户感觉「不用看题都能选对」；Q5 的例句里目标词出现 2 次以上。 |
| **对策（预防）** | ① **词库层面先保证可生成性**：见 §7.4 的「干扰项可生成性普查」，要求 Q1 可生成率 ≥ 95%、Q2 ≥ 95%，且**每个 `pos` 类别至少 12 个词**（4 类各 12 = 48 词打底，剩余 152 词按高频补），不足的词在词库阶段就补词或换词；② 干扰项**优先同 `pos` + 同 `frq` 量级**（取 `frq` 最接近的 10 个候选里随机 3 个），保证难度相当；③ 词库录入走「**双人复核**」（自己录 + 隔天再核一遍）：核对 5 项——拼写、音标、词性、释义、例句是否真的含该词；④ 用 T4.10 的 `dev/check-words.mjs` 加机器校验：`example.toLowerCase().includes(word.toLowerCase())` 必须为真、`meaning_cn` 不含「见」/「同上」等空释义、`phonetic` 必须含 `/` 或 `ˈ` 等音标符号；⑤ Q5 出题前检查例句中目标词**恰好出现 1 次**，出现 0 次或 ≥2 次则降级为 Q3；⑥ `approximate` 的处理写单测：断言 `approximate=true` 时 `consecutiveCorrect===0`、`nextReviewAt` **不变**、`wrongCount` 不增加（照 PRD §5.3）。 |
| **对策（检测）** | 自检面板（T4.8）跑「100 局出题模拟」：断言每局 4 选项齐全、Q1/Q2 首字规则 0 违反、同局词不重复、题型分布偏差 ≤ ±5 个百分点（照 A3）。 |
| **兜底** | 若某词 Q1/Q2 都无法生成合格选项：该词**只能出 Q3/Q5**（在词库里打 `tags:["spellOnly"]`），并在统计页的词库 Tab 里以中性方式标注「拼写专练」；若连 Q3/Q5 都做不了（如例句缺词），**换掉这个词**（这是词库问题，不是代码问题，不允许在代码里放宽硬规则）。 |

### R4 · 状态迁移丢失

| 项 | 内容 |
| --- | --- |
| **风险** | ① 判定后没写盘就崩/关页 → XP 丢了（PRD §1 的「随时中断不丢」是硬目标）；② `rounds` 幂等键没生效 → 结算页刷新一次多发一次奖（金币凭空翻倍）；③ 跨天瞬间答题 → 算错日期，`dailyStats`/streak 记到错误的自然日；④ 多标签页同时打开 → 后写覆盖先写，进度回退；⑤ 版本迁移漏字段 → 旧档载入后 `undefined` 引发连锁 `NaN`；⑥ 导入旧存档 → 徽章被覆盖丢失；⑦ `localStorage` 写失败（隐私模式/配额满）被当成异常抛出 → 整个判定流程中断，连内存里的进度也丢了；⑧ 对局中断后再次进入 → `session` 是内存态，刷新即丢，但已得 XP 必须留。 |
| **触发信号** | 刷新后金币少了；结算页多刷两次金币变多；Console 出现 `NaN`；切标签页回来数字回退；隐私模式下白屏。 |
| **对策（预防）** | ① **每次判定立即写盘**（T1.19 明确要求，不等结算），写盘包在 try/catch 里，失败只改 `persistStatus` 不改流程；② `roundId` 幂等键在 `applyRoundEnd` **第一行**检查（T1.18），任何重入直接 return；③ **所有日期只在两个地方生成**：开局时快照 `session.startedAt` 与 `todayKey`，整局按**开局日期**计入 `dailyStats`/streak（照 PRD §7.1 最后一行），`endedAt` 只取真实时刻（B8/B9 用）；④ `saveNow` 每次写前 `JSON.stringify` 一次、写后立刻 `getItem` 比对长度，不一致则报 `persistError`；多标签用 `storage` 事件只**提示**、等本局结束再重载（照 PRD §7.3）；⑤ `fillDefaults(save)` 在**每次 load 后无条件执行**，逐字段补全（含 `streak.freezeCards=2`、`achievements={}`、`stats.daily={}`、`byType` 5 项骨架），并对数值字段做 `Number.isFinite` 检查，非有限值回落默认；⑥ 导入时徽章取并集且保留**最早** `unlockedAt`（T3.9），`stats` 逐字段取最大值；⑦ `migrate` 里每个版本迁移函数必须是**纯函数**且可重复执行（幂等）；⑧ 对局刷新 → 回营地 + Toast「上一局已中断，已获得的 XP 与金币已保留」（照 PRD §4.2 触发入口最后一条）。 |
| **对策（检测）** | 自检面板加 4 条断言：幂等（同一 `roundId` 结算两次结果深相等）、写盘失败不中断（mock `setItem` 抛错后流程仍返回结果）、缺字段补全（`fillDefaults({})` 后所有必需键存在）、日期边界（`23:59` 开局、`00:01` 结算 → 计入开局那天）。人工验收见 §6.4 的「崩一手」清单。 |
| **兜底** | 若某用户已发生数据回退：`wordquest.save.v1.bak` 只留最近一份（这是 PRD §6.1 的定稿），因此**不承诺找回更早状态**；用「导出存档」作为用户侧的自保手段，并在设置页把导出入口放在清档入口**上方**（视觉上先看到备份，再看到危险操作）。 |

### R5 · 其他登记风险（不在任务书四条内，但同样会挡住交付）

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `file://` 下 `crypto.randomUUID()` / `crypto.subtle` 在部分浏览器不可用 | `roundId` 生成失败、导出校验失败 | `util.uid()` 已备降级（时间戳 + 随机串）；`checksum` 已备 FNV-1a 降级（T3.9） |

### 7.4 干扰项可生成性普查（替代 `distractors` 字段的关键验收）

因为干扰项是运行时生成的（PRD 裁决），词库必须在**数据层面**保证生成的可行性。普查算法（写进 `#/selfcheck` 面板，一条断言即可覆盖）：

```js
// 对 200 词里每个词 w，判断它能否出 Q1 / Q2
function canBuild(type, w, all) {
  const key = type === 'Q1'
    ? x => x.meaning_cn.trim()[0]      // 中文释义首字
    : x => x.word.trim()[0].toLowerCase(); // 单词首字母
  const samePos = all.filter(x => x.id !== w.id && x.pos && x.pos === w.pos && key(x) !== key(w));
  if (samePos.length >= 3) return true;                       // 同 pos 足够
  const relaxed = all.filter(x => x.id !== w.id && key(x) !== key(w));
  return relaxed.length >= 3;                                  // 放宽 pos 后足够（首字规则不放宽）
}
// 断言：canBuild('Q1',w) 为真的比例 >= 95%；canBuild('Q2',w) 为真的比例 >= 95%
```

| 普查结果 | 处置 |
| --- | --- |
| Q1 与 Q2 都能生成 | 正常词，什么都不用做 |
| 只有 Q1 或只有 Q2 能生成 | 该词在此题型上不参与出题（`buildOptions` 返回 `null` 时由 `questionPool` 换词），并在 README 记一笔 |
| 两个都不能生成 | 该词打 `tags:["spellOnly"]`，**只出 Q3/Q5**；若连 Q3/Q5 也不可行（例句缺词）→ **换掉这个词** |
| 某个 `pos` 类别 < 12 词 | 在 S3 阶段补录该词性的高频词，或把该类别词汇入 `user_seed` 的 40 个槽位 |

**为什么这条比预存 `distractors` 更可靠**：预存的干扰项是**静态快照**，会随词库增删而失效（删掉一个词，其他词的干扰项里可能还引用着它），而 PRD §4.4 还要求「同局内已出现的词不入干扰项」——这条是**运行时**约束，静态数据根本表达不了。普查 + 运行时生成是唯一能同时满足全部硬规则的做法。

### 7.5 词库质量的机器校验（写进 `dev/check-words.mjs`，零依赖）

| 校验项 | 规则 | 失败处置 |
| --- | --- | --- |
| 数量 | `length === 200` | 补/删词 |
| 四字段非空 | `word/phonetic/meaning_cn/example` 均 `.trim() !== ''` | 补录 |
| 唯一性 | `new Set(words).size === 200`；`new Set(ids).size === 200` | 换词 / 改 id |
| 例句含词 | `example.toLowerCase().includes(word.toLowerCase())` 且出现次数 **恰好 1** | 重写例句或换词 |
| 例句不重复 | 200 条例句两两不同 | 重写 |
| 释义可用性 | `meaning_cn` 不含 `见`、`同上`、`参见`；长度 ≤ 20 字 | 重写释义（否则污染干扰项首字规则） |
| 音标格式 | 含 `/` 或 `[` 或 `ˈ` `ə` 等音标字符 | 补录 |
| 词性白名单 | `pos` ∈ `{'v.','n.','adj.','adv.','prep.','conj.','pron.','num.'}` 或空串 | 统一写法 |
| 词性分布 | `v./n./adj./adv.` 各 ≥ 12 | 补词 |
| 干扰项可生成性 | §7.4 的 Q1/Q2 可生成率各 ≥ 95% | 按 §7.4 表格处置 |
| 长度与形态 | `word.length >= 3`；不含空格与连字符；全小写 | 换词 |
