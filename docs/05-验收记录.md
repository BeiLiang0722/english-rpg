## 3. 自检面板与三套断言说明

`#/selfcheck`（或 `node dev/selfcheck.mjs`）覆盖 36 条，分组如下：

- **等级曲线**：`needXp(1)=70`、`needXp(19)=250`、`cumulativeXpForLevel(5)=340`、`cumulativeXpForLevel(20)=3040`、`titleFor(20)='单词猎手（满级）'`、升级发 30 金币。
- **单局 XP**：上限构造成例（8 题全 Q3/Q5、全对、全为新词、命中连击 3/5/8 与完美局）= **285**；下限（非新词 1 题答对）= 15；连击三档合计 35；同档位不重复给奖。
- **单局金币**：上限构造（8 题全对）= **61**。
- **血量与连击**：3 题答错 → 血量归零且已得 XP 不变；答错扣 1 心。
- **幂等**：同一 `roundId` 结算两次深相等。
- **存档补全**：`fillDefaults({})` 后关键字段齐全且为有限数。
- **日期边界**：漏 1 天消耗 1 张冰冻卡且连击不减；漏 9 天归零 + `pendingBreak`；连续调用 3 次结果一致（幂等）；日期回拨不变更；结算分支连击 +1。
- **词库**：200 词、四字段非空率 100%、单词唯一、例句恰好含词 1 次、四个主要词性各 ≥ 12。
- **出题**：Q1/Q2 干扰项可生成率 ≥ 95%；100 局模拟（每局 8 题、选项齐全、首字规则 0 违反、同局不重复）；题型分布偏差 ≤ ±5 个百分点；拼写判定三种情形；近似正确不推进 SRS；SRS 间隔表。
- **成就**：11 条进度无 NaN；首次答对解锁且不重复发币。
- **设置**：`defaultSettings()` 恰好 5 个键。

## 5. 已知问题（如实记录）

### 5.1 验收方式相关的限制

1. **没能在真浏览器里自动跑**：本机沙箱禁止浏览器进程创建命名管道（Edge 报 `mojo platform_channel Check failed: 拒绝访问`），headless Edge 起不来。
   因此改用 Node + 极简 DOM 跑真实前端代码（73 条断言全过），**视觉部分留给人眼**（第 4 节）。
   `dev/e2e.mjs` + `dev/run-e2e.ps1` 是给正常环境准备的浏览器 CDP 版本，**在本机未验证过能否跑通**，请以 `dev/dom-e2e.mjs` 的结果为准。
2. **DOM 垫片不等于真浏览器**：垫片覆盖了事件冒泡、`data-action` 委托、`classList`、`innerHTML` 解析、`localStorage`、`location.hash`。
   但**不做 CSS 布局、不做 `innerText` 可见性判断**，所以"某个元素被遮挡/溢出"这类问题它发现不了。

### 5.2 与上游文档的口径差异（必须记录）

3. **「单局 XP 上限 215」是特例，不是全局上限**。`docs/03` §5.1 的 215 构造成例是「8 题全是 Q3/Q5 且全对且 8 个词全是新词 + 连击 + 每日首局 + 完美局」。
   若本局题型里混入 Q1/Q2/Q4（每答对基础分 10–12 而不是 15），上限会**高于** 215；本次实测就有 260 的情况。
   自检里的构造成例严格等于 **285**（`8×15 + 8×5 + 8×5 + 35 + 20 + 30 = 285`）——
   这里和 PRD 文本的 215 不一致，差在 PRD 的算式把"新词首答"和"击败新词"合起来只算了一次（`8×5`），而 §5.1 的正文明确两者可叠加。
   **本实现的取舍**：按 §5.1 的逐条规则实现（两者叠加），并在 `roundRecord.xpGained` 里只放"对局本体"收益（不含徽章/升级奖励），
   另开 `bonusXp / bonusCoins / levelUpCoins` 字段，这样「对局本体 XP」「对局本体金币」始终落在可解释区间内。
   建议：请以 PRD 为准裁定 215 的口径（是特例还是上限），若要求硬上限 215 需回改数值表。

4. **题数上限与词性分布**：为满足「v./n./adj./adv. 各 ≥ 12」并保证干扰项质量，最终 200 词里动词偏多（111 个）。
   规则上没问题（选出英文释义词时同词性候选充足），但**长时间游玩时选择题里动词占比会偏高**。这是词库取舍，不是代码问题。

5. **`app/data/words.json` 不是运行时依赖**：`file://` 下 `fetch()` 被 CORS 拦住，页面实际加载 `app/src/data/words.js`（同一份数据）。
   两份文件由 `dev/check-words.mjs --write` 同时生成，**不要手工只改一份**，否则会漂移。

### 5.3 功能层面的已知限制（v0.1 不做）

6. **没有 PWA / Service Worker**（`file://` 硬限制），没有浅色主题，没有存档导入/导出（`docs/03` §4.12 的 checksum 方案留到 v0.2）。
7. **多标签页不做实时合并**：检测到别的标签页写存档只提示一句，等本局结束后才重新读档。
8. **发音依赖系统语音包**：TTS 不可用时听音辨词题从本局题型池里移除并把权重分摊给其余题型，不影响开局。
9. **成长页的「错题本 / 统计 / 词库」是 v0.1 的简版**：四个 Tab 都有真实数据且口径正确，但统计页只做了近 7 天趋势（近 30 天与时间范围切换未做）、错题本的「移出」行内操作未做（目前只能靠"只打错词"重练来推进）、统计数据没有"以表格查看"的可访问性切换。
10. **商店与成就已接通但不是本轮重点**：4 件道具与 11 个徽章的判定、限购、待生效逻辑都在跑（C 套件断过），但徽章详情的"点卡看详情弹层"未做（当前徽章墙直接把条件与进度铺开显示）。

### 5.4 本轮修掉的真问题（留痕，避免回归）

实现过程中被自检/E2E 抓到并修复的 5 个真 bug：

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 单局 XP 比构造成例少 10 | `applyAnswer` 里 `before` 被 `srs.applyCorrect` **就地改写**后才去判「新词首答 / 击败新词」，两个 +5 永远不触发 | 先取出 `wasNewWord / wasUndefeated` 两个布尔量，再走 SRS 写入 |
| 2 | 重试后掉的血被还回来 | `retryCurrent` 用作答前快照回滚了 `hpLeft` | 重试不恢复血量（只回滚进度与连击），并注释说明 |
| 3 | 同一局可能出现重复词 | `buildRound` 取词没做去重 | 生成题目时用 `usedIds` 挡重复，并从候选池补足题数 |
| 4 | 升级覆盖层的层级不对 / 徽章金币没计入明细 | `applyRoundEnd` 里金币落库与徽章判定顺序颠倒 | 调整为「对局收益 → 徽章 → 升级 → 金币落库」，明细与合计一致 |
| 5 | 直接打开 `#/home`（带 hash 刷新）时不做跨天结算、也没有中断提示 | `main.js` 只在 `#/boot` 路径上才调用 `home.enter()` | 启动时显式调用一次 `home.enter()`，不依赖进入时的 hash |

### 5.5 交付后复验发现的问题（测试工具的，不是 App 的）

> 复验人：交付后独立复核（非实现者本人）｜ 复验命令：三套原样重跑

**现象**：`dev/dom-e2e.mjs` 不是确定性的。原记录写「73/73 通过」，但重跑 6 轮里有 1 轮变成 **71/73**，失败两条固定为：

```
FAIL  答错不加 XP  → xp=50
FAIL  重试后血量不变、题号不变  → hp=2 第 3 题
```

**根因**（两层，都在测试侧）：

1. `dom-e2e.mjs` **没有注入 `rnd`**。App 的随机源最终都落到 `Math.random`（`flow.buildRound` / `questionPool.buildRound` 在不传 `rnd` 时用它），于是每跑一次抽到的题型序列都不同。
2. 第 3 节的断言**假定「当前是第 0 题的选择题」**，但第 139 行自己定义的 `isChoice()` 与 `ensureChoiceQuestion()` 的结果没被后续断言用上——抽到首题是拼写题（Q3/Q5，无选项）时，`answerCurrent(false)` 落不进任何作答分支，**既不判定也不掉血**，连带两条断言失败。

**证据**：

| 种子 | 本局题型序列 | 结果 |
| --- | --- | --- |
| 1 | Q2,Q1,Q2,Q5,Q5,Q1,Q2,Q2 | 73/73 |
| 2 | **Q3**,Q1,Q1,Q2,Q3,Q2,Q2,Q1 | **71/73**（首题拼写） |
| 3 | Q2,Q1,Q2,Q1,Q3,Q2,Q2,Q1 | 73/73 |
| 7 | Q1,Q1,Q5,Q2,Q2,Q1,Q2,Q1 | 73/73 |

**修法**：给 `createPage()` 加可播种的 `Math.random`（mulberry32，只在 vm 沙箱内替换，不污染宿主），默认种子写死为 7，可用 `WQ_E2E_SEED` 覆盖；另加 `--find-seed` 便于以后换局。**App 代码一行未动**——这是测试工具的确定性缺陷，不改变任何产品行为。

**修复后回测**：默认种子连跑 **8 轮，8/8 全过（73/73）**。三套件复验结果：

| # | 命令 | 结果 |
| --- | --- | --- |
| A | `node dev/check-words.mjs` | 错误 0，结论 通过（200 词） |
| B | `node dev/selfcheck.mjs` | 36/36 PASS |
| C | `node dev/dom-e2e.mjs` | 73/73 通过，失败 0（可复现） |

> 遗留建议（不影响本轮验收）：第 3 节的断言可以更稳——要么像现在这样锁种子，要么让断言显式「推进到一题为选择题再开始」，两者取其一即可，不必都做。
