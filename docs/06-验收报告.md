> **关于 S4 的必要性**：三套官方套件全绿，但它们**结构性地看不见** §4 的缺陷——
> `domshim.mjs:473-480` 的 `localStorage` 垫片**永不抛错**（所以写盘失败分支在 73 条里没被覆盖）；
> `dom-e2e.mjs:64` 默认锁种子、`dom-e2e.mjs` 的「中途刷新」用例在刷新前**没有作答**（所以断言不到收益丢失）；
> 垫片**不派发 `storage` 事件**（所以多标签页路径只有静态可读）。
> 这不是套件不好，而是「套件全绿 ≠ 通过验收」的典型案例，本轮因此额外做了 S4。

### D1（高）对局中刷新丢失本局全部已得收益，但提示「已保留」

- **复现步骤**
  1. 双击 `app/index.html` → 进营地（`localStorage` 为全新档，等级 1 / XP 0 / 金币 0）。
  2. 点「开始一局」→ 进对局页。
  3. 第 1 题选**正确**选项（本局首题 Q1 时反馈条显示「✓ 答对了 +20 XP」）。
  4. 记下 Console 的 `WQ.state.session.xpGained`（实测 `20`）与 `WQ.state.session.coinsGained`（实测 `2`）。
  5. 按 **F5** 刷新。
- **期望**（PRD §4.2 触发入口 + §1「随时中断不丢：每题判定后立即落库；任何时刻退出，已得 XP / 金币都保留」）
  本局已获得的 20 XP / 2 金币进账，营地 HUD 与「今日状态」显示已得；Toast「上一局已中断，已获得的 XP 与金币已保留」成立。
- **实际**（探针 A）
  ```
  A.本局已得（内存 session）: xpGained=20 coinsGained=2 correct=1
  A.刷新前 save.profile: xp=0 coins=0 rounds=0
  A.session 键是否已写入: true
  A.刷新后 Toast: 上一局已中断，已获得的 XP 与金币已保留   ← 提示照常出现
  A.刷新后 save.profile: xp=0 coins=0 rounds=0                ← 收益一分没进账
  ```
  丢失范围不只是一局的两个数字：**本局 `progressMap`（词级 SRS 进度）、`stats.daily` / `stats.byType` / `stats.total*` 聚合、以及这条 RoundRecord 全部丢失**。
- **根因定位**
  - 逐题收益只累加在内存 `session` 上：`game/balance.js:177-178`（`session.xpGained/coinsGained`），`balance.js:259`（`session.progressMap`）。
  - 唯一把 session 收益写进 `save` 的入口是 `applyRoundEnd`（`balance.js:214`），它只被 `flow.finishSession`（`flow.js:315`，打完/血量归零）与 `flow.abortSession`（`flow.js:330`，点「✕ 退出」）调用。
  - 刷新后 `WQ.state.session` 是 `null`（`state.js:16`），`main.js:76-80` 只做 `clearSession()` + 置 `interruptNotice`，**不补结算**。
  - `flow.js:229` 的 `commit()` 写的是 `save`，而 `save` 里没有 session 的收益 → 「判完立即落库」这句只对 UI 状态成立，对收益不成立。
- **影响**：破坏 PRD 目标表第 3 行「随时中断不丢」这一硬目标；玩家真实损失进度，且被提示告知「已保留」，是**误导性**提示。
- **同类入口**：直接关闭标签页、崩溃同理（无 `beforeunload`/`pagehide` 兜底，全项目 grep 零命中）。

### D2（高）中途「✕ 退出」把未完成的局当成完成局结算

- **复现步骤**
  1. 全新档进营地，确认 `WQ.state.save.daily.todayFirstRoundDone === false`。
  2. 点「开始一局」，只答**第 1 题**（答对），然后点左上「✕」→ 弹层「退出本局？」→ 点「退出」。
- **期望**（PRD §4.2 异常情况③）
  「保留所有已得 XP/金币，**不写 `todayFirstRoundDone`（若本局未完成）**」。
  即退出后：金币/XP 有小额增加、`todayFirstRoundDone` 仍为 `false`（每日首局 +20 XP / +15 金币 留给今天真正的第一局）。
- **实际**（探针 B）
  ```
  B.开局前 todayFirstRoundDone: false
  B.退出前（未打满）: index=0/8 answers=1 hpLeft=3
  B.退出后 todayFirstRoundDone: true        ← 未完成局把每日首局标志写掉了
  ```

### D3（高）多标签页写入互相覆盖（lost update），且没有重读机制

- **复现步骤**
  1. 同一浏览器把 `app/index.html` 开成 **两个标签页**（A、B），两者共用同一 `localStorage`。
  2. 在 A 标签页打完整一局，结算落库（实测 A 侧 `xp=25 coins=209 rounds=1`，`localStorage` 里也是这份）。
  3. **不刷新** B 标签页，直接在 B 标签页做一次会写盘的操作（例如点进营地/任意 `commit()`）。
  4. 再开第三个标签页 C（或回到 A 刷新）看存档。
- **期望**（PRD §7.3「多标签页同时打开」）
  「监听 `storage` 事件；检测到其他标签页写入时，当前页 Toast『存档已在其他标签页更新』并在**本局结束后重新加载存档**（不在答题中途打断）」——
  即至少不能把对方写入覆盖掉。
- **实际**（探针 D）
  ```
  D.A 标签页结算后（落库）: xp=25 coins=209 rounds=1
  D.storage 里的存档:       xp=25 coins=209 rounds=1
  D.B 标签页内存里的旧档:   xp=0  coins=0   rounds=0
  D.B 提交后 storage 里的存档: xp=0 coins=0 rounds=0      ← A 整局进度被 B 覆盖抹掉
  D.第三个标签页读到的存档:    xp=0 coins=0 rounds=0
  ```
- **根因定位**
  - `main.js:81-84` 收到 `storageExternal` 只置 `ui.multiTabNotice = true`；`persist.js:178-181 onStorage` 只转发事件。
  - `home.js:37-40` 只把它消费成**一次 Toast**；**全项目没有任何 `loadFromStore()` 重读、没有 `location.reload()`、没有 `beforeunload`/`pagehide`/`visibilitychange` 兜底**（grep 零命中）。
  - `state.js:97-103 commit()` 把整份内存 `save` 全量 `setItem`，无版本号/时间戳/冲突检测 → 典型 last-write-wins。
  - 附带问题：提示只在**再进 `#/home`** 时消费，若用户一直停在 `#/growth` / `#/battle`，连提示都不会出现。
- **另注**：`docs/05` §5.3 第 7 条与 `README` §5.7 自述「检测到其他标签页写存档时只提示一句，**等本局结束后才重新读档**」——
  **代码里没有任何「重新读档」**，该自述与实际不符（见 D24）。
- **影响**：进度/金币可回退，属静默数据损坏；多标签是浏览器常规用法（例如手机浏览器恢复标签），不可忽略。

### D10（中，上游口径冲突，需裁决）单局 XP 上限 215 与 PRD 自身算式矛盾

- **证据（算术）**：PRD §5.1 第 351 行原文

- **判定**：这是 **PRD 文档的算术错误**，不是实现错误 —— 实现严格按 §5.1 的逐条规则落地。
- **影响**：A14 的 `10 ≤ xp ≤ 215` 断言在任何一次「8 题全 Q3/Q5 全对」的局里都不可能成立；`docs/05` §5.2 第 3 条已如实记录该冲突。
- **建议**（下一轮，需上游拍板，**不得自行改数值**）：① 把 PRD §5.1 的 215 修正为 285；或 ② 明确「上限 = 按本局题型分布逐条相加」，并把 A14 的断言改为「落在 `[10, 按题型分布上限]`」。另建议把「下限 10」补一句前提「至少 1 题答对」（8 题全跳过时本体 XP = 0）。
