## 0. 一句话结论

v0.1 的三套自动验收全绿，但**结构性地看不见**「存档一致性」这类缺陷。本轮做了两件事：

1. **修掉验收报告 P0 清单的 5 条阻塞项**（D1 刷新丢收益 / D2 中途退出吞每日首局 / D3 多标签互相覆盖 / D5 道具刷新即丢 / D4 侦查之眼无效果），
   并顺带修掉 P1/P2 里的 D6 / D7 / D8 / D9 / D15 / D16 / D18 / D20 / D21 / D22 / D23；
2. **加一层「每天都想打开」的留存机制**（每日任务 + 随机宝箱 + 错题本重练 + 成就弹窗），并把它们做成**跨天正确结算**的持久化数据。

过程中还挖出两个 v0.1 就存在、但从未被断言覆盖的**真 bug**（见 §4），它们直接影响了 `docs/06` 的 D10 结论。

## 1. 最高优先级三项修复（验收报告 §7 P0 的第 1–3 条）

### 1.1 D1 · 对局中刷新丢本局全部收益

| 项 | 内容 |
| --- | --- |
| 原来 | 逐题收益只累加在内存 `session` 上；唯一写进 `save` 的入口是 `applyRoundEnd`，而它只被「打完」或「点退出」触发。刷新后 `session` 被清掉 → 本局 XP / 金币 / 词级 SRS 进度 / stats 聚合 / 每日聚合全部丢弃，而界面还提示「已获得的 XP 与金币已保留」 |
| 现在 | `persist.saveSession()` 落**完整可结算会话**（题目 + `progressMap` + 累计收益 + 逐题日志 + 回合口径），启动时 `flow.recoverSession()` 读回并补一次 `applyRoundEnd`；`roundId` 幂等键保证「其实上次已结算成功」时不会重复发奖 |
| 文案 | 提示改为给出具体数字：「上一局已中断，已为你补结算：+N XP · +M 金币」 |
| 边界 | 会话快照结构不完整（旧版本写的键、或人为构造）时不再尝试补结算，但仍按旧行为提示一句并清键 |

### 1.2 D2 · 中途「✕ 退出」被当成完成局

| 项 | 内容 |
| --- | --- |
| 原来 | `isWin = hpLeft > 0`，1 题的中断局也是「赢」，于是写掉 `todayFirstRoundDone`（吞掉当天真正的第一局 +20 XP / +15 金币）、记一条 `isWin:true` 的 RoundRecord、`stats.totalRounds +1`、并走完整徽章判定 |
| 现在 | `abortSession` 置 `session.aborted = true`：**保留全部已得收益与词进度**（这是 PRD §4.2 异常③的要求），但 `isWin=false`、不写 `todayFirstRoundDone`、不进 `stats.totalRounds` / `daily.todayRounds` / `stats.daily[].rounds` |
| 徽章 | 中断局只放行 `ABORT_SAFE_BADGES` 白名单（累计量类：初次交锋 / 百词斩 / 老练猎人 / 猎人领袖 / 挥金如土 / 满级猎手），「首次通关 / 无伤 / 百发百中 / 早起鸟 / 夜猫子」一律不发放 |
| 兼容 | 旧存档里没有 `aborted` 标记的历史中断会话，用「血量未归零且没答完全部题」反推同一结论 |

### 1.3 D3 · 多标签页写入互相覆盖（lost update）

| 项 | 内容 |
| --- | --- |
| 原来 | 收到 `storage` 事件只置一个标志 → 下次进营地弹一次 Toast；**没有任何重读路径**，本标签下一次 `commit()` 用旧档整份覆盖对方写入 |
| 现在 | `persist.saveNow()` 写盘前做**存储指纹预检**：把 localStorage 里的存档算一个稀疏指纹，与「本页上次确认过的指纹」比较。不一致 → 先读盘 → `save.mergeSave()` 合并 → 再写 |
| 合并规则 | `rounds` 按 `roundId` 去重后合并（货币的唯一真相来源，先去重以免重复入账）；`profile`/`stats`/`streak` 逐字段取更靠后的进度；`progress` 按词取更靠后的 `lastSeenAt` 且各项计数取较大值；`achievements` 取并集（解锁不可逆）；`daily` 取 `todayDate` 更新的一份 |
| 提示 | 合并发生时广播 `storageExternal{merged:true}`，营地提示「存档已在其他标签页更新，已合并双方进度」 |
| 取舍 | 这是**合并**而不是实时同步：界面上的数字要等下一次渲染才反映对方的进度。理由是要保证「任何一方都不丢」，实时同步会引入跨页渲染耦合与中途打断 |

> 为什么指纹要「不依赖 `fillDefaults`」：读档时算的指纹与落盘后算的指纹必须能直接比较。
> 因此指纹只取 `version / level / xp / totalXp / coins / totalCorrect / totalRounds / rounds 长度 / 末条 roundId / daily.todayDate` ——
> 这些字段在「本页自己的 `commit()`」下不变，在「别的标签页写过」时必然变。

## 3. 留存机制：每日任务 + 随机宝箱 + 错题本重练 + 成就弹窗

### 3.1 为什么是这四个（而不是继续加数值）

行为设计上要让「明天再打开」有**具体的、临近的、今天就能推进一点**的理由。四个机制各承担一个不同的心理角色：

| 机制 | 承担的角色 | 为什么有效 |
| --- | --- | --- |
| **每日任务**（3 条/天，自动结算） | **今日有一次明确的收尾** | 每天只有 3 条、且 2 条常驻（登场 / 练 8 题），玩家进营地就看得见「还差 1 条」。关键是**没有「领取」按钮**、完成后自动发奖 —— 不制造打卡压力，也不给玩家「忘了领 = 白干」的惩罚感。全清额外 +20 金币 / +10 XP，把「顺手做完最后一条」变得划算 |
| **随机宝箱** | **短周期的变量奖励** | 碎片来自「每 3 次连续答对」，所以箱子出现在「再答对 3 题就够」这种**近端、可计算**的距离上；开箱结果按 60/32/8 命中普通/稀有/传说，提供不确定性的兴奋点。单日上限 3 枚碎片、最多开 1 箱、未开箱碎片次日只留 1 枚 —— 既给「今天不开就亏一点」的温和拉力，又不会因囤积让跨天数值失控 |
| **连续 7 天登录额外白送 1 箱** | **奖励「每天都来」而不是「一次打很多」** | 这是本机制里唯一直接针对「日常习惯」的钩子：连续登录的边际收益高于单日刷量 |
| **错题本重练**（冷却随错误次数缩短） | **把负面记录变成可完成的清单** | 错题本天生是「欠债清单」，只有惩罚没有出口。现在每个词给出「N 天后可重练 / 可重练」的**可操作状态**，且错得越多越快能重练（错 N 次 → N 天后，封顶 7 天）—— 把「我又错了」转化为「我明天可以把它打回来」 |
| **成就弹窗**（含 3 个新徽章） | **给长期行为一个可见的里程碑** | 新增 B12 日常猎手（首次全清当日任务）/ B13 浪子回头（重练答对 1 个词）/ B14 宝箱猎人（累计开 3 箱），三个都对准本轮新加的行为，让新机制本身也有成就叙事 |

**共同的设计约束**：所有奖励都走同一笔账（见 §4.3），所有状态都在 `localStorage` 里按**本地日期键**跨天结算，页面刷新/崩溃/多标签都不会让它们错账。

### 3.2 跨天结算的实现要点

- 三个日期键各自负责一件事：`daily.countersDate`（今日计数器）、`daily.questDate`（任务清单与状态）、`daily.chestTodayDate`（宝箱碎片上限）。任一入口调用 `quest.settle()` 都会收敛到同一结果。
- **幂等**：同一天重复调用 `settle()` 不重复发奖（`questClaimed` / `questBonusClaimed` 是幂等键）；跨天无论跳了几天，也只结算一次。
- **任务清单是确定性的**：2 条常驻 + 1 条按本地日期做确定性轮换，同一天多次进出营地拿到的清单完全一致。
- **「今日登场」不白送**：只有真正进营地/开局（`quest.enterDay()`）才算登录，纯结算路径（例如启动时恢复一局中断的对局）不会把登录任务算完成。
- **中断局与宝箱**：中断局不计完成局数、不计「一局全对」，但已得的碎片与收益照常保留。

## 4. 过程中挖出的账目/回归问题（都影响 `docs/06` 的结论）

> §4.3 是同一轮里**被修正方向**的一笔账（原结论错、现象对），§4.4 是本轮自己引入又当场修掉的回归。
> 四条都留档，因为它们的共同教训是「三套全绿的断言也可能看不见账目问题」。

### 4.1 金币/XP 重复入账（脏账，v0.1 长期存在）

- `applyRoundEnd` 按「会话本体 + 全部明细行」算出 `earnedCoins` 并加进 `profile.coins`；
  而 `achievements.checkAchievements`（徽章）、`level.applyLevelUps`（升级）、`quest.grant`（任务）
  **各自也在直接改 `profile.coins`** → 三类奖励各发两次。
- 更隐蔽的一处：判断「本局新解锁徽章」时写成 `.map(x => x.id)`，而 `getAllProgress()` 返回的是
  `{ def, progress, target, text, unlocked, unlockedAt }`（**没有顶层 `id`**）→ `x.id` 恒为 `undefined`
  → 过滤永远为真 → 「新解锁徽章」退化成「全部已解锁徽章」，导致旧徽章奖励**每局重发一次**。
  这条不会让任何单局断言失败（明细与总额同源），只有跑经济模拟才暴露：30 天收入会从 ~2100 涨到 ~8400。
- **修法（v0.2 起的账目契约）**：
  - `applyRoundEnd` 是**唯一**写 `profile.coins` / `profile.xp` 的地方；
  - `checkAchievements` 新增 `ctx.deferAward`，为真时只把应发金额放进返回值的 `award`，不写 profile；
  - `level.applyLevelUps` 默认不再写 `profile.coins`，只返回 `coinsFromLevels`（需要旧行为可传 `{credit:true}`）；
  - `quest.grant` 只记账，金额由 `settle()` 的返回值带出来，在 `applyRoundEnd` 的同一笔账里入账。
- **可断言的不变量**：**「明细行逐行相加 === 档内增量」**。
  `dev/dom-e2e.mjs` 有两条断言守着它（XP 一条、金币一条），`dev/sim-economy.mjs` 的「明细外的重复入账」列也应恒为 0。

### 4.2 「新词」判定读的是每局重置的会话（抬高单局 XP）

- `applyAnswer` 里 `before = session.progressMap[wordId] ? … : defaultProgress(wordId)`，
  而 `session.progressMap` **每局新建** → `seenCount` 恒为 0 → 同一词在每一局都被当成新词，
  「新词首答 +5」与「击败新词 +5」每局重发。
- **修法**：`before` 以 `save.progress[wordId]` 为基准（同一局内第二次作答该词时用本局已累计的值；
  免费重试时回滚到本局快照），并用 `session.progressAnswered` 标记本局已作答过的词。
- **对 `docs/06` D10 的影响**：D10 说「单局上限 215 与 PRD 自身算式（=285）矛盾，属文档算术错误」。
  现在可以说得更准确：**285 这个构造本身就吃了上述 bug 的红利**。修正后正确口径是
  「按本局题型分布 + **实际新词数**逐条相加」。`docs/06` §10.3 已留档为 `[待上游确认]`。

### 4.3 一笔被算错方向的账：「每日任务的钱到底有没有发出去」（模拟脚本口径更正）

- **旧结论（错）**：`dev/sim-economy.mjs` 的文件头曾写「`flow.js:42` 丢弃 `quest.enterDay()` 的返回值 →
  「今日登场」每天 5 金币 + 5 XP 永远发不出去（每月约 150 金币 / 150 XP）」。
- **复核（三段探针）**：现象对了一半，结论完全反了 ——
  1. 跨天后第一次 `rolloverDaily()` 内部就会调一次 `quest.settle()`（`balance.js:636`）。它把
     `daily.rollDate` 置为今天并**完成**「今日登场」（`questDone.questLogin = true`），但 `rolloverDaily`
     不消费它的返回值 —— 所以「记了账、profile 还没加钱」这个观察是**对的**；
  2. 因为已经 claimed，之后 `pages/home.js:33-51` 与 `flow.createSession`（`flow.js:43-57`）再调
     `enterDay()` 都是幂等返回 `{coins:0, xp:0}` —— 所以「返回值被丢弃导致丢钱」这个推论是**错的**；
  3. 这笔奖励在**当天第一局结算**时由 `applyRoundEnd → quest.settle()` 汇总成 `questCoins`，
     写进 RoundRecord 的 `breakdown` 行 `quest`（`balance.js:411-433,498`）。A8-2 的「每日任务 742」
     就是这个口径，**没有丢钱**。
- **本轮动作**：更正 `sim-economy.mjs` 的 NOTE3 与输出文案；模拟改为按生产顺序调用并断言
  「`enterDay()` 返回值 === `profile.coins` 增量」（正常情况下两边都是 0，一旦链路变化立刻报警，不会静默丢钱）；
  新增两条断言把这条链路钉死（每日任务金币必须经 `quest` 明细行入账且 ≤ 设计上限；
  「明细外入账」必须恒为 0）。`docs/06` §10.4 / §10.5 已同步更正。
- **顺带改正的一处配置注释**：`config/balance.js` 的每日任务注释原写「reward 合计 + 全清加成 = 65 金币 / 18 XP」，
  与实现和实测都不符。按「2 条常驻 + 当日最肥的 1 条轮换」重算：金币 `(5+15)+15+20 = 55/天`、
  XP `(5+8)+10+10 = 33/天`（`sim-economy.mjs` 的设计上限列同样输出 55/天，两边现已一致）。

### 4.4 `audio.unlock()` 会吞掉刷新后的第一次按键（本轮新引入又当场修掉）

为了让音效在首次手势后能真正出声，`audio.bindUnlock()` 在 `document` 上注册了 `keydown` 监听；
解锁成功后原本会 `removeEventListener` —— 而事件派发器**正在遍历**监听器数组，
删掉后面的监听器会让同一个事件上排在后面的处理器被跳过。
真实表现是「刷新页面后键盘用户按 `1` 作答，第一次没反应」。
修法：**不摘监听器**，改用一个幂等标志 `unlocked` 让回调只执行一次。
这条是 `dev/dom-e2e.mjs` 的「纯键盘走完一局」断言抓出来的。

## 5. 动效与音效（不引外部音频文件、不为好看牺牲加载速度）

- **动效**：全部纯 CSS keyframes（新增 14 个 `wq-` 前缀动画），JS 只负责增删状态类
  （`.stat-value.is-bump` / `.combo-badge.is-burst` / `.heart.is-losing` / `.progress > i.is-gain` /
  `.chest-icon.is-openable|is-opening|is-opened` / `.quest-row.is-unlocked` / `.levelup-flash`）。
  全部 ≤600ms（升级覆盖层整体 2.2s 属「玩家主动等待的奖励时刻」，例外），无 `infinite` 循环，
  并在 `prefers-reduced-motion` 与设置页「减弱动效」两条路径下同时降级。
- **音效**：全部用 WebAudio 实时合成（`OscillatorNode` + `GainNode` 包络），零音频文件、零网络请求。
  新增 `sfxScore` / `sfxQuestDone` / `sfxReclaim` / `sfxChestOpen(tier)`（档位越高音阶越多）；
  并补上「首次用户手势解锁 AudioContext」（`unlock()` + `bindUnlock()`），
  因为自动播放策略下只靠作答时顺手 `resume()` 可能已经错过手势窗口。
- **加载速度**：没有新增任何 `<link>` / `<script>` 之外的资源，没有 Web Font，没有图片，没有图表库；
  样式仍是原来的 4 个文件（体积从 33.8KB 增至 ~68.6KB，gzip 后约 12KB）。
  动效只用 `transform` / `opacity` / `background`，不给滚动内容加 `backdrop-filter`。

## 7. 移动端适配（360px）

- **不溢出**：长英文单词/音标/任务描述加 `overflow-wrap:anywhere`；所有可能被长内容撑开的 flex 子项补 `min-width:0`
  （`.hud-main` / `.battle-body` / `.quest-row-main` / `.deck-name` / `.spell-input` / `.chart-col`）；
  分段控件允许换行；30 列图表用 `flex:1 1 0 + min-width:0 + overflow:hidden` 收住。
- **不缩放**：`viewport` meta 维持 `width=device-width, initial-scale=1`，`-webkit-text-size-adjust:100%`，
  不设任何会触发浏览器自动放大的字号。
- **点击区 ≥44px**：`.btn` 56 / `.option` 56 / `.tile` 96 / `.speak-btn` 44 原本就够；
  本轮把 `.btn-sm` 与 `.icon-btn` 从 40 提到 44，`.seg button` 提到 44，
  `.switch` 视觉仍保持 32px 的观感但用伪元素把**命中区**外扩到 44px（不改变外观）。
- **可执行的静态检查（本轮补）**：上面三条原先只是「静态推导 + 人眼确认」，现在有 `dev/check-mobile.mjs`
  把可判定的部分变成机器检查 —— 它解析 4 个 CSS 文件与 `index.html`，断言：
  ① viewport 含 `width=device-width` + `initial-scale=1` 且未写 `maximum-scale` / `user-scalable=no`；
  ② 全局 `box-sizing: border-box`；③ `html/body` 有断行兜底；
  ④ 存在 `max-width ≤ 389px` 的 xs 断点；⑤ 页面级容器（`html/body/.page/.app-shell/main/#app`）没有
  `overflow-x: hidden` 这种「用裁剪掩盖溢出」的写法；⑥ `.btn` / `.option` / `.tile` / `.icon-btn` 的声明高度 ≥44px
  （会展开 `var(--h-cta)` / `var(--h-option)` 这类 token 再比大小）。当前结果：**通过（9 项）**。
  为确认它不是橡皮图章，做了 3 次变异测试（删 `overflow-wrap` → 报错 1 项；给 `.page` 加 `overflow-x:hidden` → 报错 1 项；
  `.btn` 的 `min-height` 改 32px → 报错 2 项），还原后回到「通过（9 项）」。
- **人工确认项**：沙箱内起不了真浏览器（headless Chromium 的命名管道被拒），
  所以 360px 的「渲染后没有横向滚动条」仍是**人工确认项**：`check-mobile.mjs` 只覆盖**声明层面**，不做像素级渲染。
  这一条如实列在 README「已知限制」与 `docs/06` §10.6，脚本文件头也写明了同样的边界。

## 10. 数据模型速查（新增字段一览）

跨天结算全部以**本地日期键**为准（不用 UTC，避免跨时区错一天）；任何入口调用 `quest.settle()` 都会收敛到同一结果。

| 字段 | 位置 | 作用 |
| --- | --- | --- |
| `daily.counters` | `save.daily` | 今日计数器（`answered/correct/wrong/combo/streakCorrect/distinctWords/newWords`），结算时由 `stats.daily` 重建 |
| `daily.countersDate` / `daily.questDate` / `daily.chestTodayDate` | `save.daily` | 三个跨天边界键：计数器 / 任务清单 / 宝箱碎片上限 |
| `daily.rollDate` | `save.daily` | 「今天打开过游戏」的标记（只有 `quest.enterDay()` 会写，纯结算路径不写） |
| `daily.questIds / questProgress / questDone / questClaimed / questBonusClaimed / questBonusDate / questRoundIds` | `save.daily` | 当日任务清单与幂等发奖状态 |
| `daily.chestShards / chestShardsToday / chestSpawns / chestOpenDate / chestHistory` | `save.daily` | 宝箱碎片、当日产出、开箱幂等键与最近 30 次记录 |
| `daily.seenToday` | `save.daily` | 今日已见词（用于「碰新词」类任务与「碰 N 个不同词」） |
| `daily.reclaimed / perfectToday / todayAttempts` | `save.daily` | 今日重练答对数 / 全对局数 / 含中断局的开局次数 |
| `profile.pendingScoutEye` / `profile.pendingStrawDouble` | `save.profile` | 待生效道具（**从顶层迁入**，修 D5） |
| `profile.chestOpenedTotal` | `save.profile` | 累计开箱数（B14 徽章进度） |
| `roundRecord.aborted` | `save.rounds[]` | 中断局标记（D2） |
| `roundRecord.questXp / questCoins / extraXp / extraCoins` | `save.rounds[]` | 任务收益单列，保证「明细逐行相加 === 顶部合计」 |

**版本策略**：`saveVersion` 保持 1 不变 —— 新增字段全部由 `fillDefaults` 做**结构补全**（含类型校验与旧顶层字段迁移），
不需要版本号升级；只有「版本号高于当前代码」的存档才会被拒绝加载（`migrate().rejected` → 本次会话不写主键）。
